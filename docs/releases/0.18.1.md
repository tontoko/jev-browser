# Jev Browser 0.18.1

This patch release keeps a `run` alive when a `commit`-classified control turns out to open an
in-page confirmation UI instead of saving. It has no breaking changes.

## Upgrading from 0.18.0

No code or configuration change is required.

- **A confirmation opener no longer ends the run unverified.** When the effect classifier labels a control `commit` but the click opens a confirmation UI on the page — no verified result record, a quiet settle window, the caller `until` condition still false — `run` now sends the changed screen back to the actor for a fresh decision instead of returning `unverified / condition-unmet`. The send-back is the same one used when a save was read through without the goal being achieved: the next decision state carries `callerCompletion: false`, and the confirmation control the click made visible is now decidable. Repeated unproductive openers stay bounded by `maxSteps` and the run's other budgets.
- **Resume reconciliation is unchanged.** Reconciling an unknown pending save on `resume()` still returns `unverified` without a new browser mutation.

## Installation

```sh
npm install --save-dev https://github.com/tontoko/jev-browser/releases/download/v0.18.1/tontoko-jev-browser-0.18.1.tgz
npx jev-browser install chromium
```

For Workers, also `npm install @cloudflare/playwright`.
