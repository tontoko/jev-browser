# Jev Browser 0.18.3

This patch release stops `run` from offering the same quoted-value fill again after the field
already holds that value. It has no breaking changes.

## Upgrading from 0.18.2

No code or configuration change is required.

- **A satisfied quoted fill is not offered again.** In a goal without `values`, each quoted string
  in the instruction becomes a fill candidate for every fillable field. The observation reports a
  field only as `filled`, so a field that started with a value looked identical before and after the
  fill, and the actor could choose the same fill until `maxSteps` ran out. `run` now reads each
  candidate's field locally and leaves out a fill whose field already matches its quoted value. The
  value is not added to the decision request.
- **A changed field gets its fill back.** If the page or another input later changes that field,
  the fill is offered again on the next turn. No retry limit or new state is added.
- **Runs with `values` are unchanged.** They never receive quoted fill candidates.

## Installation

```sh
npm install --save-dev https://github.com/tontoko/jev-browser/releases/download/v0.18.3/tontoko-jev-browser-0.18.3.tgz
npx jev-browser install chromium
```

For Workers, also `npm install @cloudflare/playwright`.
