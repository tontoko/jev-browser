# Jev Browser 0.10.0

## Breaking change: use the shared browser interfaces

The Pi-specific `@tontoko/jev-browser/pi` export, adapter, tests and guide have
been removed. SDK, persistent CLI and MCP remain the supported interfaces,
including the opt-in restricted screen mode. No replacement harness or plugin
framework was added.

Migrate a consumer away from `./pi` before changing its dependency pin. A normal
browser automation session can use DOM/ARIA-grounded Jev decisions; screen-only
operation is an opt-in capability, not a requirement for every QA workflow.
The removed adapter's environment variables are not generic MCP options; see
`docs/migration.md` for the standard interfaces and tool restrictions.

The normal build clears generated output so stale Pi files cannot leak into a
new package. Installed-package checks verify the remaining interfaces and that
the removed subpath cannot be imported.

## Installation

```sh
npm install --save-dev https://github.com/tontoko/jev-browser/releases/download/v0.10.0/tontoko-jev-browser-0.10.0.tgz
npx playwright install chromium
```

This is GitHub Release tarball distribution, not an npm registry publication.
The existing v0.9.0 release is unchanged. Dependencies retain their exact locked
versions; this release does not add image understanding, a vision provider,
model routing or a claimed speed improvement. Optional image understanding is
separate work in issue #19, with existing MM plugins as reference only.

## Release verification and recovery

A version-changing push to main publishes only after the existing six CI jobs
succeed. Publication reuses the Ubuntu/Node 24/Chromium installed-package test
artifact from that same run; it does not rebuild it. The release attaches its
SHA-256 checksum and links the exact source and CI run below. Pull-request runs
never publish, and unchanged versions skip publication.

Publication creates a new tag and a draft release before making it public.
Existing tags/assets are not replaced. A stopped publish may leave a tag or draft;
inspect that exact run and existing assets before completing it with the native
GitHub release tools. Do not delete or overwrite a published version to retry.
