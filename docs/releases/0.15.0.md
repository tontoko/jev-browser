# Jev Browser 0.15.0

This minor release lets the decision engine call Cloudflare Workers AI's System
One models (Clef, Clef-flash) directly. It has no breaking changes.

## Upgrading from 0.14.2

No code or configuration change is required. Hosted Jev and other custom
System One endpoints work as before.

- **Workers AI run URLs.** Clef follows the System One API, but Workers AI
  serves it at an account-scoped run URL, expects the model's short name in
  `model`, and wraps the answer in a v4 envelope. Set `JEV_BASE_URL` (or the
  `baseURL` option) to the run URL, for example
  `https://api.cloudflare.com/client/v4/accounts/<account>/ai/run/@cf/cloudflare/clef-flash`,
  and `JEV_ENDPOINT_API_KEY` (or `apiKey`) to a Cloudflare API token with
  Workers AI access. Decisions are posted to that URL with `model:
  "clef-flash"`, and the answer is read from `result`. A `success: false`
  envelope or an HTTP error is `PROVIDER_ERROR`; it is never read as an
  answer. Hosted Jev keys (`JEV_API_KEY`, `TYPESAFE_API_KEY`) are never sent
  to a Workers AI URL, and a run URL without a token is a `CONFIG` error.

## Installation

```sh
npm install --save-dev https://github.com/tontoko/jev-browser/releases/download/v0.15.0/tontoko-jev-browser-0.15.0.tgz
npx jev-browser install chromium
```

npm 7+ and pnpm install the `playwright-core` and `zod` peers automatically;
with Yarn Berry, add them explicitly:
`yarn add -D ./tontoko-jev-browser-0.15.0.tgz playwright-core zod`.

This is GitHub Release tarball distribution, not an npm registry publication.
Verification and recovery follow the 0.10.0 notes: publication happens from CI
only after every platform job succeeds and never overwrites an existing tag.
